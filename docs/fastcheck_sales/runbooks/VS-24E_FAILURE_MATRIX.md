# VS-24E Failure Matrix

Use this matrix during sandbox/test-mode smoke and optional low-value production
smoke. If a scenario fails differently than expected, stop the smoke, document
the finding with redacted evidence, and create follow-up work. Do not fix bugs
inside VS-24E unless explicitly instructed.

| Scenario | Trigger | Expected Customer Response | Expected Durable State | Expected Worker Behavior | Expected Operator View | Audit / Log / Evidence Safety | Result |
|---|---|---|---|---|---|---|---|
| Abandoned payment | Customer receives payment link but does not pay | No ticket link; existing pending copy only | Order remains awaiting/payment pending until expiry policy applies; no ticket issue; no attendee from payment | Expiry worker handles hold release according to existing policy | Order visible as pending/expired; no ticket issued | No raw payment URL or customer PII in evidence | Fail closed |
| Duplicate webhook | Same signed Paystack webhook is replayed | No duplicate customer message | Payment event marked duplicate or idempotent; order effects unchanged | Webhook/verification workers do not repeat payment side effects | Duplicate/idempotent state visible | No raw provider payload in logs/evidence | Fail closed |
| Provider pending | Paystack verify returns pending/non-success | No ticket link | Payment attempt remains pending/manual review per existing policy; no issuance | Verification worker retries or exits according to policy | Pending/manual review visible | No provider payload or access code leaked | Fail closed |
| Amount mismatch | Verified provider amount differs from order | Generic pending/manual review outcome | Payment attempt mismatch/manual review; order not paid; no ticket | Verification worker does not enqueue issuance | Mismatch visible without raw payload | No amount plus PII bundle in evidence | Stop ship if ticket issues |
| Currency mismatch | Provider currency differs from expected currency | Generic pending/manual review outcome | Payment attempt mismatch/manual review; order not paid; no ticket | Verification worker does not enqueue issuance | Mismatch visible without raw payload | No raw payload in evidence | Stop ship if ticket issues |
| Reference mismatch | Provider reference does not match expected attempt/order | Generic pending/manual review outcome | Payment attempt mismatch/unmatched; order not paid; no ticket | Verification worker does not enqueue issuance | Unmatched/mismatch visible | Use redacted suffix only | Stop ship if ticket issues |
| Expired checkout | Customer pays after checkout expiry or expiry races payment | Generic manual review/pending outcome | Existing expiry/late-payment policy applies; no unsafe ticket issuance | Expiry and verification workers remain idempotent | Manual review/late payment visible | No payment URL or provider payload leaked | Fail closed |
| Duplicate ticket issuer run | Issuance worker runs twice for same paid order | No duplicate customer ticket | Exactly one ticket issue and one attendee per paid unit | Worker returns idempotent success or no-op | Stable counts visible | No ticket code/hash leaked | Stop ship if duplicate created |
| WhatsApp send failure | Payment or ticket link send fails | Generic retry/fallback/manual review copy, if existing behavior supports it | Delivery attempt records failure; order/ticket state unchanged | Worker retries or moves to failure according to policy | Delivery failure visible | No message payload, phone, URL, token, or PII leaked | Fail closed |
| Secure token invalid | Operator/customer opens malformed or unknown token | Generic invalid/not-found ticket page | No ticket/order/attendee mutation | No worker side effects | Safe failure visible if observed | No token or token hash logged | Fail closed |
| Secure token expired | Customer opens expired secure ticket link | Generic expired/unavailable page | Ticket remains unchanged; no scan mutation | No worker side effects | Expired link/ticket state visible | No token/hash leaked | Fail closed |
| Revoked ticket | Revoked ticket page or scanner path is used | Ticket unavailable/not valid; scanner rejects | Ticket issue revoked; attendee scanner visibility invalidated | No issuance/delivery of valid ticket | Revocation visible with reason/audit | No QR/ticket code/hash leaked | Fail closed |
| Refunded/cancelled order | Refunded or cancelled order ticket is opened/scanned | Ticket unavailable/not valid; scanner rejects | Order terminal state; ticket/attendee not scannable | No valid delivery/resend | Refund/cancel state visible | No PII/provider payload leaked | Fail closed |
| Archived event | Ticket for archived event is opened/scanned | Ticket unavailable/not valid; scanner rejects | Event archived; ticket not renderable/scannable | No delivery of valid ticket | Event/ticket state visible | No protected values leaked | Fail closed |
| Not-scannable attendee | Attendee scan eligibility becomes not scannable | Scanner rejects | Attendee remains not scannable; invalidation visible | No acceptance mutation | Scanner visibility pending/count visible | No ticket code/QR leaked | Fail closed |
| Wrong resend identity | Customer gives non-matching identity details | Generic failure or retry copy | Challenge not verified; no delivery queued | No ticket-link worker enqueued | Safe blocked/failed state visible | No email/phone/existence leak | Fail closed |
| Wrong OTP | Customer submits invalid OTP | Generic failure/retry copy | Challenge remains pending/blocked per policy; no delivery queued | No ticket-link worker enqueued | Safe failed/attempt state visible | OTP never logged or evidenced | Fail closed |
| OTP lock/rate limit | Too many OTP attempts or resend requests | Generic blocked/rate-limited copy | Challenge blocked/locked per policy | No delivery queued | Blocked/rate-limited state visible | No OTP/public challenge ID leaked | Fail closed |
| Duplicate resend | Verified resend delivery is requested twice | At most one intended resend message for the challenge | Challenge consumed once; delivery attempt paired to internal challenge ID | Worker idempotency/dedupe prevents duplicate effect | Challenge consumed and delivery audit paired | No ticket link/token/hash in evidence | Fail closed |
| Dashboard PDF unavailable | Authenticated PDF download returns unavailable/error | Customer unaffected; no PDF attachment is sent | No ticket/order/attendee/delivery mutation | No delivery worker invoked | Safe failure response visible to admin | No ticket code/token/hash in headers/evidence | Fail closed |
| Scanner accepts invalid ticket | Revoked/refunded/cancelled/archived/not-scannable ticket scans successfully | Not applicable; operator must stop test | Invalid acceptance is a data integrity incident | Stop workers/checkouts as directed by incident owner | Incident visible/escalated | Evidence uses IDs only; no QR/ticket code screenshot | Stop ship |
